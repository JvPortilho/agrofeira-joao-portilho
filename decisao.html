1. Objetivo

Este registro apresenta as decisões tomadas durante o desenvolvimento do projeto AgroFeira, considerando o uso de CSS autoral, Bootstrap e Tailwind.

Também são apresentados os resultados dos testes de responsividade, acessibilidade, validação de formulários e carregamento de JavaScript.

2. Comparação das alternativas

Comparação entre as abordagens de estilo
Critério CSS autoral Bootstrap Tailwind
Organização Estilos definidos nos arquivos CSS do projeto. Utilização de componentes e classes prontas. Utilização de classes utilitárias.

3. Resultados dos testes

3.1 Menu responsivo

O catálogo Bootstrap foi testado na largura de 360 pixels. O menu apresentou o botão de abertura e os cinco links de navegação.

Durante a inspeção, o atributo aria-expanded apresentou o valor true com o menu aberto e false com o menu fechado.

3.2 Janela de detalhes do açaí

O botão "Ver detalhes" abriu uma janela contendo a imagem, o nome do produto, o produtor, o preço e a descrição.

A janela foi testada em 360 pixels. O fechamento pela tecla Esc funcionou e o foco retornou ao botão de origem.

3.3 Validação do formulário

O formulário de fechamento do pedido possui os campos Nome completo, E-mail e aceite das regras da feira.

Ao tentar enviar o formulário vazio com JavaScript ativado, foram exibidas mensagens de erro abaixo dos campos.

3.4 Teste sem JavaScript

Com o JavaScript desativado, o formulário continuou visível, mas deixou de apresentar as mensagens de validação.

Como o formulário utiliza novalidate, o navegador permitiu o envio dos campos vazios por meio do método GET.

Limitação identificada: a validação personalizada depende da execução do arquivo validacao.js.

4. Medição do JavaScript

O tamanho dos arquivos JavaScript foi observado utilizando a aba Network das ferramentas de desenvolvedor do Chrome.

Resultados registrados no navegador
Arquivo Transferido Recurso
bootstrap.bundle.min.js 25,2 kB 80,5 kB
validacao.js 0,6 kB 0,6 kB

O Bootstrap disponibiliza funcionalidades prontas para o menu e a janela de detalhes. O arquivo validacao.js foi utilizado especificamente para a validação do formulário.

5. Acessibilidade

Foram utilizados elementos semânticos, rótulos nos campos do formulário, textos alternativos nas imagens e atributos ARIA nos componentes interativos.

No formulário, aria-describedby relaciona cada campo à sua mensagem de erro. No catálogo, aria-expanded informa o estado do menu responsivo.
